# what2eat · 今天吃什么

一个替你做决定的吃饭小程序。你只需要回答两个问题——「今天正常吃还是放纵一下」「这顿就吃这个吗」——剩下的：吃多少、吃什么、怎么搭、下顿怎么收、超了之后怎么匀回来，它都算好了。

**纯前端、无后端、零上传**：没有账号、没有服务器、没有埋点，所有数据只存在你手机本地（微信 storage）。卸载即消失。

## 为什么做这个

市面上的吃饭 App 把「吃什么」当搜索问题：给你一个几万条目的库，让你自己筛。但每天中午十二点的真实体验是——你不想当采购员在货架前挑，你想要一个直接能执行的答案，而且这个答案得讲道理：合你的口味、在你的热量账内、今天放纵了明天知道怎么补。

所以 what2eat 的设计原则是**输出决定，不输出清单**：

- 打开就是今天还能吃多少 kcal，而不是让你去搜
- 推荐的是一套完整搭配（主餐 + 饮品），不是单品
- 每个数字都有来路：预算怎么算的、这顿占了多少、超了怎么匀
- 你保留两个最高级别的决定权：正常 / 放纵，接受 / 换一个

## 功能详解

### 1. 每日预算

首次录入性别、年龄、身高、体重、运动量、目标，之后每天自动出账：

- 基础代谢（BMR）：Mifflin-St Jeor 公式
- 每日总消耗（TDEE）：BMR × 活动系数（久坐 1.2 到极高 1.9 五档）
- 按目标修正：减脂 −400 / 维持 0 / 增肌 +250，设 800 kcal 安全下限
- 三餐配额 3 : 4 : 3，今日页直接显示早/午/晚各自能吃多少

示例：24 岁 / 175cm / 70kg 男生、轻度运动、维持体重 → 基础代谢 1679，每日预算 2309 kcal，午餐配额 924 kcal。

### 2. 搭配推荐

点「给我推荐」，出来的是一套组合，不是一个单品：

- 主餐从 146 条品类级食物库抽取：米饭套餐 / 面粉 / 饺子馄饨 / 西式快餐 / 轻食沙拉 / 粥汤肠粉 / 麻辣烫冒菜七大类
- 饮品按场景决策：放纵日必配且优先含糖；减脂模式只从零卡池抽（无糖茶、无糖可乐、冰美式）；平时按口味与概率
- 每套推荐显示：总热量、蛋白/碳水/脂肪、占本餐预算百分比、一句怎么吃的建议
- 打分机制是偏好加权随机：常吃类型 ×1.6、口味命中逐项递增、价格带匹配 ×1.25，再叠随机扰动防止天天同一个答案
- 忌口（辣 / 油炸 / 内脏 / 香菜）是硬排除，不参与打分讨价还价
- 「换一个」会排除已出过的答案，连换最多 6 个不重样

### 3. 放纵模式

开关一拧，当日预算 ×1.3，推荐池放开高糖高油并必配饮品。当天超支的部分，未来 3 天每天自动扣回 1/3——账还平，节奏不崩。不想要这个机制，「我的」页可以切成「只记账不惩罚」（反弹研究里依从性更好的宽松口径）。

### 4. 步数换额度

今日页输入步数，按体重换算额外消耗直接加进预算：每步 ≈ 体重(kg) × 0.00045 kcal，70kg 走一万步 ≈ +315 kcal。走了路就有的吃，只加不减。

### 5. 附近找店

推荐了黄焖鸡，想知道附近哪家最近？接入高德后：定位 → 搜 1.5km 内对应品类的店 → 点店家唤起微信内置地图导航。按品类搜店，不含菜单——高德 POI 没有菜单数据，这是能力边界，不装。

### 6. 自定义食物

食堂窗口、家门口那家店，几十秒加进池子：名称、类别、热量、三大营养素、份量、价格。主餐选类型后进对应品类池参与偏好加权；删除不影响历史记录。

### 7. 账本

近 7 天摄入 vs 预算：超支红字、放纵日打标、步数留痕；当天明细可删可改，删除的热量自动从账上扣回。

## 算法与口径

| 项 | 取值 | 来源 / 说明 |
|---|---|---|
| BMR | Mifflin-St Jeor | Mifflin MD, St Jeor ST, et al. Am J Clin Nutr. 1990;51(2):241-247 |
| 活动系数 | 1.2 / 1.375 / 1.55 / 1.725 / 1.9 | FAO/WHO/UNU Human Energy Requirements (2004) 分段 |
| 三餐配比 | 3 : 4 : 3 | 常规三餐分配 |
| 步耗 | 体重(kg) × 0.00045 kcal/步 | 公开步耗估计（万步 ≈ 300–400 kcal @70kg）取保守值 |
| 放纵上浮 | ×1.3，超支 3 天线性分摊 | 设计值：上浮幅度定在「能解馋」与「会失控」之间 |
| 食物热量 | 品类级估算，**误差 ±20%** | 同一道菜各家做法热量可差一倍，这是外卖场景的结构性现实 |

**精度声明：本工具做的是预算管理，不是精确计量。** 页面底部也标着同一句话。本工具不构成医疗建议；有疾病或特殊营养需求请遵医嘱。

## 架构

纯前端小程序，无后端、无云函数、无统计 SDK。分层原则：**算法全部纯函数化，`wx` API 只出现在 store.js 一个文件里**——所以算法层可以脱离微信环境用 Node 直接测试：

```
data/foods.js        146 条内置食物库（品类级营养估算）
utils/nutrition.js   BMR/TDEE/预算/超支分摊/步数换算 —— 纯函数
utils/recommender.js 搭配推荐引擎 —— 纯函数，加权随机
utils/store.js       本地存储层 —— wx API 只在这一个文件里
pages/today|record|me|food  四个页面，逻辑薄、以展示为主
tests/               51 项离线断言
```

本地存储共四个独立键：用户画像、按日饮食流水、自定义食物、高德 Key。

### 验证

算法层 51 项断言，覆盖公式数值、放纵上浮、超支分摊数学（昨日超 300 → 今日扣 100，连续 3 天超 300 → 今日扣 300）、忌口硬排除 60 次抽样、减脂饮品零卡约束、换一个不重复、步数换算与自定义食物：

```bash
node tests/test-algo.js    # 28 项：预算 / 推荐引擎
node tests/test-batch2.js  # 23 项：步数 / 自定义食物 / 复合场景
```

## FAQ

**Q：为什么不能自动读我的外卖订单？**
美团/饿了么没有面向个人的开放 API，微信小程序生态也拿不到竞对数据。现实替代路径是导出支付宝/微信支付账单 CSV 解析高频店画像（路线图中）。第一版用「手动勾偏好」冷启动，10 分钟出画像。

**Q：为什么步数要手动输入？**
`wx.getWeRunData` 返回的是加密数据，解密需要 session_key，而获取它必须用 AppSecret 走服务端——AppSecret 不能放进前端代码，纯前端方案在安全上不成立。手动输入 + 自动换算是零依赖的稳妥解，自动拉取需要可选云函数（路线图）。

**Q：我的数据在哪？**
你手机里，全部。没有账号、没有上传、没有埋点。清空按钮在「我的」页。

**Q：能正式发布给别人用吗？**
可以，但正式版有额外门槛：合法域名配置、用户隐私保护指引声明、类目审核（健康营养相关类目对个人主体的开放范围以平台最新规则为准）。自用和给朋友扫开发版/体验版二维码没有这些门槛。
